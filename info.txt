## PHASE 4: IMAGE WATERMARK REMOVER

Create a complete image-processing tool.

### Supported inputs

Initially support:
- PNG.
- JPG and JPEG.
- WebP.

Configure file size limits according to actual browser performance and implementation capabilities. A reasonable initial limit is 10 MB per image, with a configurable option to increase it after testing.

### Upload functionality

Implement:
- Drag-and-drop upload.
- Click-to-upload.
- Clipboard paste when supported.
- Multiple image uploads.
- Upload validation.
- Image thumbnails.
- File names, dimensions, and file sizes.
- Individual file removal.
- Clear-all control.
- Duplicate-file handling.

### Processing engine

For eligible Gemini-generated images:
- Detect supported visible watermark patterns.
- Determine whether the detected mark matches a supported variant.
- Apply an appropriate verified restoration method.
- Prefer mathematically justified reverse-alpha-blending restoration when the watermark's compositing parameters are known.
- Use an alternative method only when its actual functionality has been verified.
- Preserve unaffected image regions.
- Avoid cropping, blurring, or replacing image regions unnecessarily.
- Validate the result before presenting it as successful.

If the watermark cannot be confidently detected, do not silently modify the image. Show an informative error or unsupported-image message.

Do not assume all Gemini outputs use the same watermark size, opacity, placement, or compositing method.

### Image preview

Display:
- Original image.
- Processed image.
- Before-and-after comparison slider.
- Zoom controls.
- Original and output dimensions.
- File sizes.
- Processing status.

### Image export

Allow:
- Downloading a processed image individually.
- Downloading multiple processed images in a ZIP file.
- Selecting supported output formats.
- Preserving transparency when the format supports it.
- Maintaining original resolution wherever possible.

Never enable the download button until a genuine processed output exists.

- Preview player.

### Video processing engine

Implement actual frame-by-frame processing for eligible videos.

The processing workflow should:

1. Load and validate the video.
2. Decode the video using a supported browser API or verified media library.
3. Detect supported visible watermark patterns.
4. Determine the watermark's location and size.
5. Process the relevant region of each frame.
6. Maintain temporal consistency between consecutive frames.
7. Avoid visible flicker, smearing, or changes outside the affected region where feasible.
8. Preserve the original video dimensions.
9. Preserve audio whenever technically possible.
10. Encode the resulting video into a verified output format.
11. Validate the output before offering the download.

The implementation must not claim that a watermark is removed from every frame unless the processing pipeline actually processes and verifies the relevant frames.

### Video timeline and controls

Include:
- Video preview.
- Play and pause.
- Timeline and seek controls.
- Processing progress percentage.
- Current frame or elapsed processing time where available.
- Estimated remaining time only when a defensible estimate can be calculated.
- Cancel processing.
- Retry after failure.
- Output preview.

### Audio and quality

Preserve audio and synchronization where possible.

Display any changes caused by decoding, frame-rate conversion, or re-encoding.

Do not promise pixel-perfect video output, unchanged bitrate, or lossless re-encoding unless the selected implementation genuinely guarantees it.

Explain any browser limitations.

### Video download

- A working download button.
